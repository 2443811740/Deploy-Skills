# BC/HBM Inference Consistency

## 目标

在相同模型、配置和样本条件下，找到 Python BC 参考链路与 C++ HBM 板端链路最早出现差异的位置，以最小改动完成修复并留下可复现证据。

本 Skill 描述定位方法，不预设某个模型必须使用固定归一化参数、固定 Tensor 数量或固定输入顺序。

## 适用范围

- BC 与 HBM 推理结果不一致。
- Python 与 C++ 的模型输入、输出或最终结果不一致。
- 需要用参考 NPY 在板端逐组替换输入定位问题。
- 怀疑图像、LiDAR、时序输入、量化、内存布局或后处理存在差异。

以下情况不直接使用本 Skill：

- 只有性能问题，没有正确性参考结果。
- 两条链路使用了不同模型或不同样本，且暂时无法统一。
- 目标只是部署已有产物，不涉及结果对齐。

## 必需信息

开始修改或远程操作前，确认并记录：

- 参考链路启动命令及真实模型调用路径。
- 目标链路构建、部署和运行命令。
- 唯一样本或帧标识，以及各传感器文件清单。
- 两侧代码版本、模型 SHA256 和配置 SHA256。
- 模型输入输出的名称、shape、dtype、layout 和量化信息。
- 目标设备、部署目录、产物名称和结果回收目录。
- raw Tensor 与语义结果各自的通过阈值。

缺少会改变实验结论的信息时先询问；不得把密码、令牌或私钥写入 Skill、manifest 或报告。

## 不可破坏的原则

- 每次实验只改变一个因素，并保留可回退的原始基线。
- 参考输入必须在真正的模型调用边界捕获，而不是来自更早的训练或浮点中间状态。
- 已量化 Tensor 不得二次量化。
- 优先按 Tensor 名称匹配；只有模型元数据确认一致后才能依赖索引。
- 未经用户授权，不覆盖已有配置、模型、运行库或结果文件。
- 调试 dump 和输入覆盖必须显式启用，默认路径保持原行为。
- 可视化只能辅助判断，不能代替数值和语义验收。

## 工作产物

从 [运行清单模板](./assets/run-manifest.json.template) 创建本次 `run-manifest.json`，并从 [实验报告模板](./assets/experiment-report.md.template) 创建报告。所有 dump、比较结果和结论必须能通过这两个文件追溯。

## 工作流

### 1. 冻结比较契约

1. 选择一个确定样本，调试阶段默认只运行第一帧。
2. 记录两侧代码版本、模型、配置、命令和环境。
3. 对模型、配置和输入文件计算 SHA256。
4. 保存两侧完全原生运行的输出，禁止先修改再补基线。
5. 确认输入数据没有跨帧残留：相对路径基于数据清单所在目录解析，每帧开始前清空可缺失传感器的容器。

任何契约项变化后，旧实验不得与新实验直接比较。

### 2. 捕获参考链路

1. 从启动脚本追踪本次实际执行的模型分支，不根据函数名猜测。
2. 在 BC `.feed()` 或等价模型调用边界捕获全部输入。
3. 输入应是完成预处理和量化后、真正交给模型的 Tensor。
4. 同时捕获模型原始输出和最终语义结果，区分反量化前后数据。
5. 为每个 Tensor 记录 name、index、group、dtype、shape、layout、量化状态和 SHA256。
6. dump 逻辑必须由环境变量或显式开关控制，并支持限制帧数。

使用 [Tensor 边界说明](./references/tensor-boundary.md) 检查捕获位置和元数据。

### 3. 验证 Tensor 契约

1. 从 BC dump 与 HBM 模型元数据分别生成输入清单。
2. 按名称建立映射，再验证 index、dtype、valid shape 和 layout。
3. 明确每个 NPY 是浮点数据、待量化数据还是已经量化的数据。
4. 文件传到板端后重新计算 SHA256。
5. 在映射、shape、dtype 或量化状态不明确时停止回放，不进行猜测性拷贝。

可运行 [manifest 校验脚本](./scripts/validate_manifest.py) 检查文件、哈希与 NPY 元数据。

### 4. 建立差分实验矩阵

按以下顺序执行，并将每次实验写入报告：

| 实验 | 目标链路输入 | 用途 |
|------|--------------|------|
| `native` | 全部使用 C++ 原生输入 | 建立目标基线 |
| `all-reference` | 全部使用 BC dump | 判断模型运行时和输出链路是否一致 |
| `group-reference` | 每次只替换一个语义组 | 定位图像、LiDAR、时序等输入组 |
| `single-or-stage` | 替换单个 Tensor 或比较单阶段中间量 | 找到最早差异 |
| `fixed-native` | 修复后恢复全原生输入 | 验证最终实现 |

判定规则：

| 现象 | 下一步 |
|------|--------|
| `all-reference` 的 raw 输出仍不一致 | 检查模型产物、运行时、输出量化解释和模型绑定 |
| raw 输出一致但最终结果不一致 | 检查反量化、解码、过滤、序列化和可视化 |
| `all-reference` 一致、`native` 不一致 | 问题位于输入读取或前处理 |
| 替换某个输入组后恢复一致 | 下钻该组的逐阶段数据 |
| 所有单组替换均无效 | 检查多输入耦合、时序状态、配置和未记录的全局状态 |

### 5. 在目标运行时安全回放

1. 只替换当前实验声明的 Tensor，其余输入保持原生。
2. 写入前清零目标缓冲区的 padding。
3. 按 valid shape、aligned shape 和实际 stride 拷贝，禁止把连续 NPY 直接覆盖到未知布局。
4. CPU 写入设备可见缓冲区后，在提交推理前执行对应 cache clean。
5. 日志打印实际替换的 Tensor 名称、index、shape 和文件哈希。
6. 不修改模型产物和部署文件的原始名称。
7. 每次运行重置可能影响结果的时序缓存和输入容器。

### 6. 下钻前处理

从原始数据开始逐阶段比较，找到第一个超过阈值的阶段：

1. 文件读取和传感器集合。
2. 坐标系及外参变换。
3. 空间范围过滤和边界包含规则。
4. voxel 坐标、尺寸、原点、排序和容量限制。
5. pillar 或其他特征通道及其归一化。
6. layout、cast、量化、padding 和最终模型输入。

LiDAR 任务必须使用 [LiDAR 前处理清单](./references/lidar-preprocess.md)。过滤范围、voxel 范围和 feature 归一化是不同概念，不得因为数值相近而合并解释。

图像/GDC、相机投影与 LSS、栅格地图或时序输入任务还必须使用 [多模态前处理清单](./references/multimodal-preprocess.md)。单帧通过后，带时序状态的模型至少再验证两个连续帧和序列重置。

### 7. 比较输出

按证据强度从高到低比较：

1. 原始模型输出 Tensor。
2. 反量化后的 Tensor。
3. 解码和过滤后的结构化结果。
4. 序列化文件。
5. 可视化结果。

使用 [输出比较规则](./references/output-comparison.md) 选择指标。NPY 可使用 [Tensor 比较脚本](./scripts/compare_npy.py)，结构化 JSON 可使用 [结果比较脚本](./scripts/compare_results.py) 或项目已有的语义比较器。

脚本依赖声明在 [requirements.txt](./scripts/requirements.txt)；缺少依赖时先报告，不得在未获授权时修改项目或系统 Python 环境。

### 8. 实施最小修复

1. 修复第一个有证据的差异，不同时重写整条链路。
2. 模型相关常量优先改为语义明确的配置项。
3. 新配置未提供时保持现有行为，除非用户明确要求改变默认值。
4. 检查共享前处理的所有调用方，区分真正共享路径与独立模型路径。
5. 对低于验收阈值的标定精度或浮点尾差记录后接受，不为追求逐位一致引入复杂实现。

某次实验发现的具体数值只能进入报告或案例，不能上升为所有模型的固定规则。

### 9. 清理与最终验证

按照 [收口清单](./references/finalization.md) 完成：

1. 删除临时硬编码和无用插桩，保留的调试能力必须默认关闭。
2. 重新构建最终产物并按原名称部署。
3. 不加载任何参考 NPY，执行 `fixed-native`。
4. 确认运行成功、输出达到阈值且没有调试 dump 残留。
5. 校验板端产物与回收文件 SHA256。
6. 在实验报告中写明根因、最小修复、验证证据和剩余风险。

## 完成标准

只有同时满足以下条件才可声明对齐完成：

- 比较契约和 Tensor manifest 完整。
- 已证明差异属于输入、模型运行时、后处理或状态中的哪一层。
- 找到了最早出现差异的可复现证据。
- 修复后的全原生目标链路达到预先定义的阈值。
- 最终运行未依赖 NPY 覆盖或临时调试代码。
- 最终部署产物、配置和结果均有可核验的版本或哈希。
