# Deployment Session Intake

## 目标

每次新对话开始后、首次执行开发动作前，向使用者确认本次会话的构建、Python/BC 参考链路、部署、板端环境和验收契约。答案只在当前对话中复用；新对话必须重新询问，不静默沿用历史会话或工作区中的旧值。

## 强制时机

当前项目安装了 `.deploy/`，且本次对话请求代码/配置修改、构建、BC 推理、部署、板端运行、模型验证或相关故障排查时，立即执行问询。

必须在以下动作之前完成对应组：

- 第一次实质性代码或配置编辑
- 第一次编译、打包或模型转换命令
- 第一次连接 Python/BC 服务器或执行 BC 推理
- 第一次上传、覆盖、进程启停或板端命令

纯解释、只读代码审查或方案讨论仍先确认任务范围；使用者明确选择“纯分析，本次不构建、不跑 BC、不部署、不上板”后，可以继续而不补问不相关细节。

## 问询方式

优先使用结构化提问工具，一次展示五组问题。每组允许选择 `provided`、`not-applicable` 或 `unknown`，不要拆成连续打断式问答。

使用 [会话问询模板](./assets/session-intake.md.template)。

### 1. 任务范围与版本

至少确认：

- 本次范围：纯分析、修改不构建、构建、BC 参考推理、部署、板端验证
- 项目/工作区根目录和目标分支或 revision
- 基线版本、目标版本及变更文档位置（适用时）

### 2. 编译与产物

至少确认：

- 编译环境：宿主机、容器、远程机或 CI
- 编译环境的连接/进入方式，以及编译前准备脚本
- 精确工作目录和编译命令
- 预期产物及路径

### 3. Python/BC 参考推理

至少确认：

- 本次是否需要 Python/BC 参考结果、输入输出 dump 或开环代码对比
- BC 服务器的连接方式：SSH alias，或非敏感的 host/user/port 与认证方式
- 服务器上的代码仓库/工作目录、目标 revision 和环境准备命令
- 精确的 BC 推理命令及其工作目录
- BC 模型、配置、数据清单/case 和固定样本位置
- BC 输出、可视化和 dump 目录
- 是否允许修改 Python 代码增加 dump/CPU 对照，以及恢复要求

禁止询问或记录服务器密码、令牌、私钥内容和口令。需要秘密认证时，让使用者直接在终端提示中输入。

### 4. 部署与板端环境

至少确认：

- 目标平台/板型和连接方式或已配置别名
- 上传方式、板端目标目录和需要部署的文件
- 是否允许覆盖，以及备份/回滚要求
- 进程或服务的停止、启动方式
- 板端登录后的环境准备命令、runtime/library 环境变量
- 模型、配置、标定、测试数据和运行工作目录
- 精确的板端运行命令

### 5. 验收

至少确认：

- 固定测试样本、帧范围或 case
- 输出、日志和可视化结果位置
- 正确性、可视化、性能或稳定性通过标准
- 结果回收方式和是否允许覆盖既有结果

## 回答状态

每一组必须标记为：

- `provided`：使用者提供了本次会话可用的值。
- `not-applicable`：使用者明确本次不涉及该阶段。
- `unknown`：当前不知道，保留为阻塞项。

不能把沉默、历史聊天、README 示例或自动探测结果当作 `provided`。使用者回答“沿用项目默认”时，先读取默认配置并把解析出的实际命令/路径回显确认。

## 会话内复用

- 问询完成后，在当前对话上下文维护 sanitized 的 `Deployment Session Contract`。
- 同一对话中不重复询问已经确认且未变化的字段。
- 用户改变目标版本、编译环境、BC 服务器/命令、目标板、部署目录或运行命令时，只重问受影响组。
- 不把“已问过”状态或回答写入项目持久文件；下一次新对话必须重新问。
- 上下文压缩后继续使用本会话已确认的契约，不因压缩重复询问。

## 阻塞与降级

- `not-applicable` 不阻塞不相关工作。
- `unknown` 不阻塞只读分析和不依赖该信息的代码修改。
- 即将进入构建、BC 推理、部署或板端验证时，对应组仍为 `unknown`，必须停止该阶段并补问。
- 不得猜测编译命令、BC 服务器/目录/命令、板端目录、服务名、设备地址或环境变量。
- 用户拒绝提供某项时，明确说明因此无法执行的阶段和剩余风险。

## 敏感信息

- 不通过提问工具、对话日志、候选日志或项目文件收集密码、令牌、私钥和口令。
- 可以记录非敏感 SSH alias、用户名、端口、密钥文件别名或认证方式。
- 命令需要秘密输入时，让使用者直接在终端提示中输入，Agent 不读取、不转发、不持久化。
- 最终答复和日志中对设备地址等非必要环境信息做最小披露。

## 与候选经验收集的关系

会话问询只建立执行契约，不自动生成候选 Skill。任务验证完成后，仍按 `alignment-skill-journal` 独立判断是否产生新的可复用对齐经验。

## 完成标准

- 新对话首次开发动作前已完成一次问询。
- 五组信息都有 `provided`、`not-applicable` 或 `unknown` 状态。
- 即将执行的阶段不存在对应 `unknown` 阻塞项。
- BC 参考链路需要时，服务器连接、环境、精确命令、模型/配置/数据和 dump 位置完整。
- 没有收集或持久化秘密。
- 同一对话不重复问，新对话不静默复用旧答案。
